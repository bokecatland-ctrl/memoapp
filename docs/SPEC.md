# クイックメモアプリ 仕様書

Oct 30, 2026 · @Vicente

## 目的と背景

勤務中に思いついたことを、ポストイットに書く速さでスマホに残し、無くさず、種類ごとに見分けられるようにする。

- 今は紙の切れ端に書いているが、置き場所の管理が大変で無くしてしまう
- すぐ書かないと忘れるので、起動から記録までが数秒で終わることが最重要
- Google Keepはプライベートのメモが多く、仕事のメモが埋もれる
- Notionは多機能すぎて、目的の画面にたどり着くまでが長い
- 紙の良さ(速い・デスクに貼って目に入る)はアプリでも再現する

## 前提条件

| 項目 | 内容 |
| --- | --- |
| 利用者 | 自分ひとり(共有機能なし) |
| 用途 | 仕事専用。プライベートのメモは入れない |
| 端末 | Android(Chrome)がメイン入力、職場PCでボード表示 |
| 同期 | スマホとPCで同じデータを見る(クラウド保存) |
| 公開先 | Vercel(希望休アプリと同じ環境) |
| 扱う情報 | 自分の業務メモのみ。ゲストの個人情報は書かない |
| 費用 | 無料枠で運用。AI APIは最小版では使わない |

個人情報は書かないが業務内容は含むため、URLを知っているだけで見られる状態にはせず、自分だけがログインできる形にする。

## カテゴリ設計

メモは4カテゴリ+受信箱に分け、ポストイットのように色で見分ける。

| カテゴリ | 色 | 音声キーワード | 期限 | 終わり方 |
| --- | --- | --- | --- | --- |
| アイデア | 黄 | 「アイデア」 | なし | アーカイブ |
| やること | ピンク | 「やること」「タスク」 | 任意で設定 | 完了チェック |
| 覚えておくこと | 青 | 「覚えておく」「メモ」 | なし | 不要になったらアーカイブ |
| 共有事項 | 緑 | 「共有」「伝える」 | 任意で設定 | 「伝えた」チェック |
| 受信箱 | グレー | キーワードなし | なし | 1タップで上の4つへ仕分け |

- 完了・アーカイブしたメモは消さずに「済み」一覧へ移す(あとで見返せるように)
- 共有事項には、伝える相手を短く書ける任意の欄をつける

## 機能仕様(最小版)

最小版はこの6機能に絞り、起動から保存まで数秒で終わることを最優先にする。

1. **クイック入力**
   - 起動直後に入力欄へフォーカス。テキストを打って送信ボタン(またはEnter)で保存
   - 入力欄の横にカテゴリの色ボタンを並べ、押せばそのカテゴリで保存。押さなければ受信箱
2. **音声入力**
   - 大きなマイクボタンを画面下(片手で届く位置)に配置
   - ブラウザ標準の音声認識(Web Speech API、日本語)で文字起こし。無料
   - 話し終わったら自動で保存。直後に数秒「取り消し」を表示
3. **キーワードでの自動分類**
   - 先頭の言葉がカテゴリのキーワードなら、そのカテゴリに入れてキーワード部分は本文から除く
   - 例:「やること、明日までにグラス発注」→ やること/本文「明日までにグラス発注」
   - 「今日」「明日」「〇日まで」などが含まれていれば期限候補として自動設定
4. **一覧とカテゴリ切り替え**
   - 「すべて」と各カテゴリのタブ。カードは色付きのポストイット風
   - タップで編集、スワイプまたはボタンで完了・アーカイブ
5. **ピン留めボード**
   - 大事なメモにピンをつけると、画面最上部のボードに常に表示
   - 紙をデスクに貼る代わり。PCで開きっぱなしにする想定
6. **期限の表示順**
   - 開いたとき「期限切れ」「今日」のものを一覧の一番上に赤系の帯で表示
   - 通知は最小版では送らない

## 画面構成

画面は1枚が基本で、スマホは「すぐ書く」、PCは「貼って眺める」に寄せる。

**スマホ(縦1列)**

1. 上:ピン留めボード(横スクロールの小さなカード)
2. 中:期限切れ・今日の帯 → カテゴリタブ → メモ一覧
3. 下(固定):入力欄、カテゴリ色ボタン、大きなマイクボタン

**PC(横長)**

- 左:ピン留めボードを大きく表示(デスクに貼った付箋の代わり)
- 右:期限切れ・今日の帯とカテゴリ別の一覧
- 上部に入力欄。音声はなくてもよい(キーボード入力が主)

**ホーム画面アプリ化(PWA)**

- Androidのホーム画面に追加して、アプリのように1タップで起動
- アイコン長押しから「音声で記録」をすぐ開けるショートカットをつける

**テーマ(ライト/ダーク)**

- スマホやPCの表示設定に合わせて、ライトとダークを自動で切り替える(prefers-color-scheme)
- アプリ内に「自動/ライト/ダーク」の切り替えも置き、選んだものは端末に保存する
- ダークの背景は温かみのある黒(#1C1B19)。付箋の色はライトより少し落ち着いたトーンにし、文字は暗い色のまま
- 色はCSS変数で一元管理し、両テーマで同じ変数名を使う
- デザイン案:[クイックメモ デザイン案](https://claude.ai/artifact/G53gdkHJpJvMYcFjJQhTAw)

## 技術構成とデータモデル

希望休アプリと同じくVercelで公開し、スマホとPCの同期のためにクラウドのデータベースを使う。

| 役割 | 候補 | 補足 |
| --- | --- | --- |
| 画面 | Next.js(React) | Vercelと相性が良い |
| データ保存・同期 | Supabase(無料枠) | 希望休アプリで別のDBを使っていればそちらに合わせる |
| ログイン | Supabaseの認証(Googleログイン) | 自分のメールアドレスだけ許可する |
| 音声 | ブラウザ標準のWeb Speech API | AndroidのChromeで動作。無料 |
| アプリ化 | PWA(manifest+service worker) | オフライン中の入力は端末に一時保存し、つながったら送信 |

**データモデル(memosテーブル)**

| 項目 | 型 | 内容 |
| --- | --- | --- |
| id | uuid | メモID |
| body | text | 本文 |
| category | text | inbox / idea / todo / remember / share |
| due\_date | date | 期限(任意) |
| share\_to | text | 共有事項の相手(任意) |
| pinned | boolean | ピン留め |
| status | text | active / done / archived |
| source | text | text / voice |
| created\_at, updated\_at | timestamp | 作成・更新日時 |

具体的なライブラリやDBの選定は、Claude Codeに希望休アプリの構成を見せたうえで最終決定する。

## 今後の拡張候補とClaude Codeへの進め方

最小版を1〜2週間使ってから、足りないと感じたものだけを足す。

**拡張候補**

- 期限の時刻指定とプッシュ通知
- AIでの自動分類・要約(Claude APIなど。Claudeの有料プランとは別料金)
- 全文検索
- 写真の添付(ホワイトボードや紙メモを撮って残す)

**Claude Codeでの進め方**

1. この仕様書をリポジトリに置き、Plan modeで実装計画を出してもらう
2. 画面だけ先に作り、端末保存で動かして操作感を確認する
3. Supabaseとログインをつないで、スマホとPCの同期を確認する
4. 音声入力とキーワード分類を追加し、勤務中の騒がしい環境で試す
5. PWA化してAndroidのホーム画面に追加、Vercelに公開する
