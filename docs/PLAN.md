# 実装計画

仕様書(`docs/SPEC.md`)の「Claude Codeでの進め方」の5手順に沿って進める。

## 構成の決定(希望休アプリ `offrequest` の確認結果)

| 項目 | 希望休アプリ | クイックメモ | 理由 |
| --- | --- | --- | --- |
| 画面 | React 18 + Vite + TypeScript | 同じ | 仕様書の候補は Next.js だが、希望休アプリに合わせる。サーバー側の処理は不要で、Vite の方が軽く起動も速い |
| DB | Supabase | Supabase(別プロジェクト) | 希望休アプリと同じサービス。無料枠はプロジェクト2つまで |
| ログイン | なし(URLの鍵+管理者パスコード) | Supabase Auth の Google ログイン | 仕様書どおり「自分だけがログインできる形」。URLの鍵方式は使わない |
| 公開 | Vercel(noindex ヘッダー) | 同じ | `vercel.json` の noindex 設定も同じにする |
| テスト | Vitest | 同じ | |

## 手順と内容

### 手順1 仕様書を置いて計画を作る ✅

- `docs/SPEC.md`、この `docs/PLAN.md`

### 手順2 画面だけ先に作り、端末保存で動かす ✅

- データは `localStorage` に保存。保存処理は `src/lib/memoStore.ts` の `MemoStore` インターフェースの裏に隠し、手順3で Supabase 版に差し替える
- 作るもの
  - クイック入力(起動時フォーカス、Enter で受信箱、色ボタンでそのカテゴリに保存)
  - カテゴリタブ(すべて/受信箱/4カテゴリ/済み)、色付きのポストイット風カード
  - 受信箱カードの1タップ仕分け
  - タップで編集(本文・カテゴリ・期限・共有の相手・ピン)
  - 完了/伝えた/アーカイブのボタン、直後の「取り消し」
  - 済み一覧(戻すこともできる)
  - ピン留めボード(スマホ:上部の横スクロール、PC:左に大きく)
  - 「期限切れ」「今日」の帯
  - テーマ:自動/ライト/ダーク(CSS変数、選択は端末に保存)
- 作らないもの(後の手順):音声入力、キーワード分類、ログイン・同期、PWA

### 手順3 Supabase とログインをつなぐ ✅

- `supabase/migrations/0001_init.sql`:`memos` テーブル(仕様書のデータモデル+`user_id`)、RLS で本人かつ許可メールのみ
- 許可するメールアドレスは `allowed_emails` テーブル(公開リポジトリなのでコードには書かない)
- `CloudMemoStore`:画面にはすぐ反映し、未送信の箱から順に送る。電波がないときは端末に残して再送
  (手順5の「オフライン中の入力」の中心部分はここで済ませた)
- Realtime と、アプリに戻ったとき・つながったときの読み直しで PC とスマホを同期
- 端末保存のデータを初回ログイン時にクラウドへ移す

### 手順4 音声入力とキーワード分類 ✅

- Web Speech API(`ja-JP`)、大きなマイクボタン、話し終わりで自動保存+数秒の取り消し
- 先頭キーワードでカテゴリ判定(本文から除く)、「今日」「明日」「〇日まで」で期限候補
- キーワード判定は純粋な関数にしてテストを書く。テキスト入力にも同じ判定を使う
- 決めたこと
  - 音声は句読点が入らないことが多いので、キーワードのあとの区切りはなくてもよい。
    ただし「メモ」「共有」「タスク」は普通の言葉の頭(メモ帳・共有スペース・タスク管理)と区別するため、区切りが必要
  - 期限の候補は、期限のあるカテゴリ(やること・共有事項)だけに入れる。受信箱からそこへ仕分けたときにも読み取る
  - 曜日(「金曜まで」)や「来週」はまだ読まない。使ってみて必要なら足す

### 手順5 PWA 化と公開

- manifest(アイコン長押しの「音声で記録」ショートカット)、service worker
- オフラインでも画面自体が開けるよう、service worker で画面のファイルをキャッシュ(未送信の保持は手順3で済み)
- Vercel に公開
